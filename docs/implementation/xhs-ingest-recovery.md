# 小红书收藏失败与原位恢复

实现范围对应 #37 工单；代码分支从 main `352a88d1ce81cdacd291ce28342efc310ca081e4` 创建。没有重试真实收藏、访问生产 Store、调整 Tokyo 或改动 Incoming 输入表单。

## 行为

- 保存失败依然保留原分享文字和原链接。前端只投影 XHS 的 `failed / partial / complete` 状态，失败或部分完成显示「小红书 · 待补全」；没有图片本身不代表失败，也不会创建假图片。
- 查看待补全收藏时，可明确点击「重新读取来源」。POST `/api/pocket/items/:id/retry-source` 使用现有 Owner API 鉴权（Bearer / 同源 Drawer 会话 / 原有本机信任），只接受空请求体。来源取自已存物件的 originalUrl，没有替换来源 URL 的参数。
- 一次重试最多 30 秒（含排队、抓取、图片和最终发布），同物件并发合并，全局最多 8 个活动请求；不后台重试。客户端等待最多 35 秒。忽略取消的迟到抓取结果没有写入资格。
- Store 原子更新同一 ID，保留备注、标签、分组、状态、回复、已读状态、非 XHS 附件和 Capture 手工标题。重试只记录 source_refreshed，不新增 received 或增加 receivedCount。重新分享仍保持原来的接收计数与重新未读语义。
- 只有非删除 XHS 物件的相同 noteId 或精确 original/canonical URL 才参与匹配。多个候选、目标变化或 noteId 已属另一物件时返回 409，不静默合并、不下载图片、不自动修复旧重复物件。
- 已成功下载的图片按原有来源键复用。部分失败可再试；完整成功的重试为幂等回执。失败抓取不把已有 complete/partial 内容降级。取消/失败的未引用新附件会清理。
- DNS、TLS、超时、HTTP 拒绝、跳转、响应限制和解析变化使用固定安全错误消息；不记录上游原始错误正文。未扩大 XHS/CDN 主机白名单，没有代理、Cookies、登录绕过或外部下载器。
- 失败 XHS 的内容读取仅返回已存分享文字及明确警告；不会隐式触发通用网页读取。

## 边界与后续发布

本机合成未知短链接的有界只读诊断得到解析失败分类；不能由此推断用户原来 `fetch failed` 的具体外部根因。上游不可访问或要求登录时仍可能无法补全，不承诺所有小红书链接都能抓取。

精确链接匹配不能提前识别所有尚未解析的不同短链接别名；解析后身份冲突会明确停止。已有真实重复收藏不自动合并。

本机没有运行中的 Docker daemon，且 Poppler 不可用；Docker smoke 与强制 PDF E2E 由 PR CI 单独验证。移动 Safari 真机和生产出口连通性仍需 EE 独立授权验收。

本 PR 不执行部署或迁移。若以后获准发布，必须先完成独立备份/恢复门槛；代码回滚可回到先前版本，新增 sourceData 字段兼容旧 schema，不以回滚生产数据卷代替代码回滚。真实收藏重试仍需 EE 明确授权。
